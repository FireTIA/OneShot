## Настройки

### Доработано меню `SETT_menu`

Теперь меню настроек поддерживает следующие пункты:

1. `OS_Target`
2. `Hide_Password_AP`
3. `Hide_Pin_AP`
4. `Hide_MAC_AP`
5. `Change_MAC_WlanX_Startup`
6. `Macchanger_Output_Mode`
7. `Hello_banner`
8. `Check_Corp_AP_Action`
9. `Check_Corp_AP_lTX_Value`
10. `Check_Corp_AP_Recheck_After_lTX`

Раньше часть настроек была в конфиге, но не имела полноценного редактирования через меню. Теперь для каждой настройки добавлен отдельный интерактивный выбор.

## `OS_Target`

- Добавлен выбор стандартных путей:
  - `Kali` → `/home/kali/OneShotPin_Log`
  - `NetHunter` → `/sdcard/nh_files/OneShotPin_Log`
- Добавлена поддержка кастомного пути.
- Если указан кастомный путь, он используется как есть.
- Если значение пустое, используется путь по умолчанию.
- Улучшено описание настройки в меню.

---

## `Hide_Password_AP`

- Доделано меню выбора режима отображения пароля AP.
- Поддерживаются режимы:
  - `False` — показывать пароль полностью.
  - `Half` — скрывать пароль частично.
  - `True` — скрывать пароль полностью.
- Настройка влияет только на вывод в терминал.
- В лог-файл пароль сохраняется полностью.

---

## `Hide_Pin_AP`

- Поддерживаются режимы:

- Настройка влияет только на вывод в терминал.
- В лог-файл PIN/PBC сохраняется полностью.

- Доделано меню выбора режима отображения MAC/BSSID точки доступа.
- Поддерживаются режимы:
  - `False` — показывать MAC полностью.

- В лог-файл MAC/BSSID сохраняется полностью.

---

## `Change_MAC_WlanX_Startup`

- Доделано меню управления сменой MAC-адреса Wi-Fi интерфейса при запуске.
- Поддерживаются варианты:
  - `False` — не менять MAC.
  - `True` — использовать `macchanger -a`, случайный MAC с сохранением OUI.
  - `True-r` — использовать `macchanger -r`, полностью случайный MAC.
  - `Custom MAC` — вручную указанный MAC-адрес.
- Добавлена нормализация значений `True`, `False`, `True-r` и кастомного MAC.

---

- Поддерживаются варианты:

  - `pretty` — красивый вывод Current/Permanent/New MAC.
- Исправлен pretty-режим, который раньше мог ломаться из-за вложенных f-string.

## `Check_Corp_AP_Action`

Добавлена настройка действия при обнаружении потенциально корпоративных/управляемых точек доступа.

Поддерживаются варианты:

- `None` / `Ask` — спрашивать пользователя каждый раз.
- `yes` — продолжать выполнение без изменений.
- `ltx` — пытаться занизить TX Power.
- `no` — завершать работу скрипта.

Это позволяет заранее выбрать сценарий поведения и не отвечать вручную каждый раз.

---

## `Check_Corp_AP_lTX_Value`

Добавлена настройка значения TX Power для режима `lTX`.

Поддерживаются варианты:

- `None` / `Ask` — спрашивать значение вручную.
- `1-30` — использовать указанное значение в dBm.

Добавлена проверка диапазона:

- значения ниже `1` приводятся к `1`;
- значения выше `30` приводятся к `30`;
- некорректный ввод сбрасывается в `None`.

Важно: реальное изменение TX Power зависит от драйвера, чипсета и regulatory-настроек. Некоторые адаптеры могут принимать команду, но фактически оставлять прежнее значение мощности.

---

## `Check_Corp_AP_Recheck_After_lTX`

Добавлена настройка повторной проверки эфира после попытки занизить TX Power.

Поддерживаются варианты:

- `None` / `Ask` — спрашивать каждый раз.
- `True` — всегда повторять проверку.
- `False` — не повторять проверку и продолжать после lTX.

## Известные ограничения

- `lTX` не гарантирует изменение TX Power на всех адаптерах.
- Некоторые драйверы могут принимать команду `iw set txpower`, но фактически оставлять прежнюю мощность.
- Для встроенных путей `OS_Target` лучше использовать значения `Kali` и `NetHunter` в правильном регистре.
- Для кастомного пути рекомендуется указывать абсолютный путь, например `/home/firehost/OneShotPin_Log`.
- Файл логов хранит полный PSK/PIN/BSSID, даже если в терминале включена маскировка. Это сделано намеренно.
